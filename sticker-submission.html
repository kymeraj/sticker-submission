Three uses, two deliverables3つの用途、成果物は2つ

“Message”, “Stamp” and “Reaction” are three ways people use a set — not three sets to build. On both platforms they collapse into two deliverables. 「メッセージ」「スタンプ」「リアクション」は、使われ方が3通りあるという話であって、3種類つくるという話ではありません。どちらのプラットフォームでも成果物は2つに収まります。

There is no separate Reaction asset to build. Reaction reuses the emoji set on LINE and the sticker pack on Apple. What changes is legibility, not geometry — a reaction renders small, and that is a looking decision, not a spec. リアクション用に別途つくるものはありません。 LINEでは絵文字セット、Appleではステッカーパックがそのままリアクションになります。変わるのは寸法ではなく「読めるかどうか」です。リアクションは小さく表示されるので、これは仕様ではなく目で見て判断することです。

Build the bundlesバンドルを書き出す

node scripts/sticker-pack.mjs <sheet.png> <out> --platform line-emoji   --rows R --cols C --expect N
node scripts/sticker-pack.mjs <sheet.png> <out> --platform line-sticker --rows R --cols C --expect N
node scripts/sticker-pack.mjs <sheet.png> <out> --platform apple --apple-size large --rows R --cols C --expect N

Each bundle holds the stickers at the platform’s own size, an upload/ folder with the extra images the submission form asks for, and a SUBMIT.md recording what was built against the published limits. 各バンドルには、そのプラットフォームの寸法で書き出したスタンプ本体、申請フォームが求める付随画像を入れた upload/、そして公開仕様に対して何を書き出したかを記録した SUBMIT.md が入ります。

Every deliverable is rendered from the source sheet at its native target size. The 180px set is an output, not a master — upscaling 180 to Apple’s 618 would ship a soft sticker, and the sheet has the resolution to do it properly. すべての成果物は元のシートから、その寸法で直接書き出します。 180pxのセットはマスターではなく出力のひとつです。180pxをAppleの618pxに拡大すると眠い絵になります。元シートには必要な解像度があります。

Apple MessagesApple Messages への申請

A sticker pack ships through the App Store like any app. The template needs no code, but it does need a Mac, Xcode, and a paid Apple Developer Program membership. ステッカーパックは通常のアプリと同じくApp Store経由で配信します。テンプレートにコードは不要ですが、Mac・Xcode・有料のApple Developer Program登録が必要です。

Before you start事前に必要なもの

  • A Mac with Xcode. The Sticker Pack App template contains no code.Mac と Xcode。Sticker Pack Appテンプレートにコードは含まれません。
  • An Apple Developer Program membership — paid, annual.Apple Developer Program のメンバーシップ（有料・年額）。
  • The bundle: --platform apple --apple-size large (300 = small, 408 = medium, 618 = large).バンドル: --platform apple --apple-size large（300=small、408=medium、618=large）。

Create the projectプロジェクトを作成する

  1. Xcode → File → New → Project…Xcode → File → New → Project…

  2. iOS tab → Sticker Pack App → Next.iOS タブ → Sticker Pack App → Next。

  3. Set Product Name and Team → Next → choose a location → Create.Product Name と Team を設定 → Next → 保存先を選択 → Create。

Add the stickersスタンプを追加する

  1. Open Stickers.xcstickers in the project navigator and select the Sticker Pack inside it.プロジェクトナビゲータで Stickers.xcstickers を開き、中の Sticker Pack を選択します。

  2. Drag every sticker PNG from the bundle’s top folder into the pack. The order in the catalog is the order users see.バンドル直下のPNGをすべてパックにドラッグします。カタログ上の並び順がそのまま利用者に見える順序になります。

  3. Worth doing: with a sticker selected, fill its Accessibility Description. The --labels names are already in each filename, so it is a copy across — and it is what VoiceOver reads out.やっておく価値あり: スタンプを選択し Accessibility Description を入力します。--labels の名称がファイル名に入っているので写すだけで済み、VoiceOverはこれを読み上げます。

  4. Select the Sticker Pack itself → Attributes inspector → Sticker Size → Small / Medium / Large, matching what you built.Sticker Pack自体を選択 → Attributes inspector → Sticker Size → 書き出したサイズに合わせて Small／Medium／Large を選びます。

Install the app iconアプリアイコンを差し込む

  1. In Finder, replace the .stickersiconset folder inside Stickers.xcstickers with upload/iMessage App Icon.stickersiconset from the bundle. It holds all eight slots plus the Contents.json Xcode expects.Finderで、Stickers.xcstickers 内の .stickersiconset フォルダを、バンドルの upload/iMessage App Icon.stickersiconset で置き換えます。8スロットとXcodeが要求する Contents.json が入っています。

  2. Reopen the catalog and confirm no well is empty. If Xcode shows a slot the bundle did not fill, render it from icon-1024x768.png.カタログを開き直し、空のスロットがないか確認します。バンドルが埋めていないスロットが表示された場合は icon-1024x768.png から作成します。

  3. These icons are 4:3 crops of a sticker — correct and buildable, but wrong as a brand mark, because nothing complex reads at 54×40. Replace them with a designed icon before you submit.生成されたアイコンはスタンプを4:3で切り出したものです。ビルドは通りますが、54×40では細かい絵は読めないためブランドマークとしては不十分です。申請前に、専用にデザインしたアイコンへ差し替えてください。

Test on a device実機で確認する

  1. Select a connected iPhone and Run. Messages launches with the pack in the app drawer.接続したiPhoneを選んで Run。Messagesが起動し、アプリドロワーにパックが表示されます。

  2. Check three things by hand: the stickers appear at a sensible size; peeling one onto a message bubble works; and on iOS 18 or later, long-press a message, swipe across the Tapback row, and pick a sticker as the reaction. That last one is the “Reaction” use — there is no separate asset for it.手で3点確認します。スタンプが妥当な大きさで出るか。吹き出しに貼り付けられるか。そして iOS 18以降 でメッセージを長押しし、Tapbackの列を横にスワイプしてステッカーをリアクションとして選べるか。最後のこれが「リアクション」の用途で、専用の素材は要りません。

Upload and submitアップロードと申請

  1. Set the target’s Bundle Identifier and Signing team.ターゲットの Bundle Identifier と Signing のチームを設定します。

  2. Choose Any iOS Device as the destination → Product → Archive.配信先に Any iOS Device を選び → Product → Archive。

  3. In the Organizer: Distribute App → App Store Connect → Upload.Organizerで Distribute App → App Store Connect → Upload。

  4. In App Store Connect, fill Name, Subtitle, Category (Stickers), Description, Keywords, Support URL, Privacy Policy URL, Age Rating, and the App Privacy questionnaire.App Store Connectで、名称・サブタイトル・カテゴリ（Stickers）・説明・キーワード・サポートURL・プライバシーポリシーURL・年齢制限、そしてApp Privacyの質問に回答します。

    The single highest-value line in that description: say the stickers appear inside Messages, not on the Home Screen. See How people get it.説明文で最も効く一文はこれです。スタンプはホーム画面ではなくメッセージApp内に表示される、と明記すること。 入手の流れタブを参照。

  5. Upload screenshots for each device family. App Store Connect lists the exact sizes — take them from the device in step 11, showing the pack open in Messages.対応デバイスごとのスクリーンショットを用意します。必要な寸法はApp Store Connectに表示されます。手順11の実機で、Messages上にパックを開いた状態を撮るのが早いです。

  6. Set pricing and availability, attach the build, then Add for Review → Submit for Review. Review is manual.価格と配信地域を設定し、ビルドを紐づけて Add for Review → Submit for Review。審査は人手で行われます。

The scripted pathコマンドラインで行う

Steps 14–18 have a command-line equivalent. The App Store Connect API key is issued at team scope — one key, one issuer, one team, shared by every project. Never generate a key per project. 手順14〜18はコマンドラインでも実行できます。App Store Connect APIキーはチーム単位で発行され、1つのキー・1つのIssuer・1つのTeamをすべてのプロジェクトで共有します。プロジェクトごとに新しいキーを作らないでください。

A CI runner or agent shell may not have the $HOME you expect. Where it differs from the account that owns the credentials, ~/.appstoreconnect/… silently resolves to the wrong home and the identifiers read as unset. Source them explicitly. CIランナーやエージェントのシェルでは $HOME が想定と異なることがあります。認証情報を持つアカウントと $HOME が異なる場合、~/.appstoreconnect/… は黙って別のホームを指し、識別子は未設定として読まれます。明示的に読み込んでください。 

# the account that owns the App Store Connect credentials
ASC_HOME="$HOME"
eval "$(grep -E '^export (ASC_KEY_ID|ASC_ISSUER_ID|APPLE_TEAM_ID)=' $ASC_HOME/.zshrc)"
ASC_KEY_PATH="$ASC_HOME/.appstoreconnect/private_keys/AuthKey_${ASC_KEY_ID}.p8"

xcodebuild -project StickerPack.xcodeproj -scheme StickerPack \
  -destination 'generic/platform=iOS' \
  -archivePath build/StickerPack.xcarchive \
  DEVELOPMENT_TEAM="$APPLE_TEAM_ID" archive

# ExportOptions.plist with destination = upload sends it in the same step
xcodebuild -exportArchive -archivePath build/StickerPack.xcarchive \
  -exportOptionsPlist ExportOptions.plist -exportPath build/export \
  -authenticationKeyID "$ASC_KEY_ID" \
  -authenticationKeyIssuerID "$ASC_ISSUER_ID" \
  -authenticationKeyPath "$ASC_KEY_PATH"

The same key triple signs an ES256 JWT for api.appstoreconnect.apple.com, which is what would drive the metadata, screenshots and review submission in step 16–18. Expect a brand-new app’s first submission to still need the UI for agreements and the App Privacy questionnaire. 同じ3点セット（Key ID・Issuer ID・.p8）で api.appstoreconnect.apple.com 用のES256 JWTに署名できます。手順16〜18のメタデータ・スクリーンショット・審査提出はこれで自動化できます。ただし新規アプリの初回申請は、契約への同意とApp Privacyの回答のため画面操作が必要と考えてください。

Enrol in the App Store Small Business Program before your first sale. Under $1M in annual proceeds it cuts Apple’s commission from 30% to 15% — $0.84 net on a $0.99 pack instead of $0.69. It is an application, not automatic. 初回販売の前に App Store Small Business Program に登録してください。 年間収益100万ドル未満であれば手数料が30%から15%になります。0.99ドルのパックで手取りが0.69ドルから0.84ドルに変わります。自動適用ではなく申請制です。

There is no way to distribute a sticker pack to other people without the App Store — TestFlight for testers, App Store for everyone else. Running from Xcode covers only your own connected device. App Storeを通さずに他人へ配布する方法はありません。テスターにはTestFlight、一般にはApp Storeです。Xcodeからの実行は自分の実機だけです。

LINE Creators MarketLINE クリエイターズマーケットへの申請

Stickers and Emoji are separate product types with separate specs. A set intended for both is submitted twice, from two bundles. スタンプと絵文字は別の商品種別で、仕様も別です。両方で出すなら、2つのバンドルから2回申請します。

Before you start事前に必要なもの

  • A LINE account — the same one you use in the app; registration is tied to it.LINEアカウント。普段アプリで使っているものと同じで、登録はこれに紐づきます。
  • Creator registration: name and email, confirmed by email.クリエイター登録: 氏名とメールアドレス、確認メールでの承認。
  • Payout details — bank account or PayPal, plus tax information — to receive earnings.分配金の受け取りに必要な送金先情報（銀行口座またはPayPal）と税務情報。

Revenue split: LINE pays out 50% of sales after the 30% platform fee taken by Apple, Google or the other storefront. 分配: Apple・Googleなど各ストアの手数料30%を差し引いたのち、その50%がクリエイターに支払われます。

Register登録する

  1. Go to creator.line.me and click Register.creator.line.me を開き 登録 をクリックします。

  2. Log in with your LINE account credentials and fill in your creator information.LINEアカウントでログインし、クリエイター情報を入力します。

  3. Confirm your registration from the email LINE sends.LINEから届く確認メールで登録を完了します。

Create the itemアイテムを作成する

  1. From the dashboard start a New Submission and choose the product type — Sticker or Emoji. They do not share a submission.管理画面から 新規登録 を開き、商品種別を選びます（スタンプ または 絵文字）。両者は別々の申請です。

  2. Enter the basic information and choose the set size: 8, 16, 24, 32 or 40 for static stickers (8 or 16 for animated). Emoji sets take 8–40.基本情報を入力し、セットの個数を選びます。静止スタンプは 8・16・24・32・40（アニメーションは8または16）。絵文字は8〜40です。

  3. Fill the Product Details screen: title and description per language, creator name, copyright holder, and category. The default language is what everyone outside your added languages sees.商品情報 の画面を埋めます。言語ごとのタイトルと説明、クリエイター名、著作権者、カテゴリ。追加した言語以外の利用者には、既定言語の内容が表示されます。

Price, submit, release価格設定・申請・リリース

  1. Set the price from the tiers offered. The floor is 50 coins (about ¥120) — see the Pricing tab for why an 8-sticker set belongs there.提示された価格帯から販売価格を設定します。下限は 50コイン（約120円）です。8個セットをそこに置くべき理由は価格タブを参照してください。

  2. Work through the preview screen and look at every sticker as it will appear in a chat. This is the last cheap moment to catch a bad one.プレビュー 画面で、トーク上での見え方を1つずつ確認します。安く直せる最後のタイミングです。

  3. Request review. It takes a few hours to about two days. LINE notifies you by message from its official account.リクエスト（審査申請）。数時間〜2日程度かかります。結果は公式アカウントからのメッセージで届きます。

What the market actually does実際の相場

When Sensor Tower surveyed the premium packs on the iMessage App Store, 86% were at $0.99, 12% at $1.99, 1% at $2.99, and exactly one app sat higher. That survey is from the store’s early years, so read it as the shape of the market rather than today’s census — but $0.99 has remained the default. Apple now offers price points down to $0.29. Sensor Tower が iMessage App Store の有料パックを調査したところ、86%が0.99ドル、12%が1.99ドル、1%が2.99ドルで、それより高いものは1本だけでした。ストア初期の調査なので現在の実数ではなく相場の形として読むべきですが、0.99ドルが標準であることは変わっていません。現在Appleは0.29ドルまでの価格帯を用意しています。

On LINE, 50 coins is where independent creator sets sit. Above it is where official and brand sets live. LINEでは個人制作のセットは50コインに集中しています。それより上は公式・ブランドのセットの領域です。

Eight is LINE’s minimum set size, and the price tiers do not scale with count. A buyer sees your 8-sticker set beside a 40-sticker set at the identical price. At eight you have no pricing power — take the floor. 8個はLINEの最小構成で、価格帯は個数に連動しません。 購入者には、同じ価格の40個セットと並んで表示されます。8個では価格の交渉力がないので、下限を選ぶのが正解です。

The economics, honestly収益の実際

LINE pays 50% of revenue after the storefront fee — Apple 26% in Japan from 1 January 2026, Google Play 30%, LINE STORE 30%. That lands at roughly 35% of gross, about ¥42 a set. LINEの分配は各ストア手数料を差し引いた後の50%です。手数料はApple（日本、2026年1月1日から）26%、Google Play 30%、LINE STORE 30%。結果として総額の約35%、1セットあたり約42円になります。

Two numbers matter more than the rate: the payout threshold is ¥1,000 (about 24 sales) and the transfer fee is ¥495 for a Japanese bank account. Requesting a payout the moment you cross the threshold hands half of it to the bank — let it accumulate to several thousand yen first. 分配率より効いてくる数字が2つあります。送金申請は1,000円（約24セット）から可能で、日本の銀行口座への振込手数料は495円です。しきい値に届いた時点で申請すると半分が手数料に消えます。数千円まで貯めてから申請してください。

At eight stickers this is not a revenue play. The value is a working pipeline that turns one artwork sheet into two storefronts. 8個のセットは収益事業にはなりません。 価値は、1枚の作品シートを2つのストアに載せられるパイプラインが手元にあることです。

Two levers worth more than the price価格より効く2つのレバー

  • Set size. Going from 8 to 16 or 24 at the same tier is the single biggest conversion lever on LINE. It needs new artwork, not new tooling. セットの個数。 同じ価格帯のまま8個から16個・24個に増やすことが、LINEでは最も効く改善です。必要なのは新しい作品であって、新しい仕組みではありません。
  • Which editions you list, and where. English and Japanese are separate products on both platforms — the text is baked into the pixels. And the buying experience splits them: lead the English edition on Apple and the Japanese edition on LINE. The reasoning is on the How people get it tab. どの版を、どこで出すか。 文字は画像に焼き込まれているため、英語版と日本語版はどちらのプラットフォームでも別商品です。さらに購入体験が両者を分けます。英語版はApple、日本語版はLINEを主戦場に。理由は入手の流れタブにあります。

Before you submit申請前に

The build checks what a machine can check. Everything below the line is what only a person can judge — and those are the usual rejection causes. 機械で確認できることはビルドが確認します。その先にあるのは人にしか判断できないことばかりで、リジェクトの原因はたいていそちら側にあります。

Checked automatically自動で確認される

sticker-pack.mjs reports these and exits non-zero on any failure: sticker-pack.mjs は以下を報告し、いずれかが満たされなければ異常終了します。

  • Image dimensions exactly at the platform’s spec, even-numbered for LINE.各プラットフォーム仕様どおりの寸法。LINEでは偶数ピクセル。
  • The per-file size cap — 1 MB for LINE, 500 KB for Apple — with the largest file named.1ファイルの上限（LINEは1MB、Appleは500KB）。最大のファイル名も表示されます。
  • The set count against LINE’s 8 / 16 / 24 / 32 / 40.セット個数がLINEの 8／16／24／32／40 に合っているか。
  • Real alpha, and every visible pixel attributed to exactly one sprite.実際のアルファ値の有無、そして見えているピクセルがすべて1つのスプライトに帰属しているか。

Only a person can judge人にしか判断できない

  • Rights to the artwork. Both vendors reject anything resembling a third party’s character, logo or photograph. If the sheet came from a generator or a marketplace, settle that you hold the rights to sell it before you submit. 権利関係。 他者のキャラクター・ロゴ・写真に似たものは、どちらの審査でも通りません。生成ツールやマーケットプレイス由来のシートなら、販売できる権利があるかを申請前にはっきりさせてください。
  • Prohibited content under each vendor’s guidelines. 各社ガイドラインで禁止されている内容にあたらないか。
  • Legibility at the size people actually see. A LINE emoji is used inline at text size; a Tapback reaction is smaller still. 実際に表示される大きさで読めるか。 LINE絵文字は本文と同じ大きさで使われ、Tapbackのリアクションはさらに小さくなります。
  • A designed app icon for Apple, replacing the generated placeholders. Apple向けの専用にデザインしたアプリアイコン。生成された仮アイコンと差し替えます。
  • Store copy — title, description, keywords. A marketing decision, not an asset one. ストア用の文章（タイトル・説明・キーワード）。素材の問題ではなくマーケティングの判断です。
